# R5.2 — Canonical Panel Unification

## Decision

There is one Runtime Intelligence product UI: `LdsDebugPanel`.

React does not get a parallel dashboard. The mature panel remains intact and receives framework-neutral UREP evidence through a compatibility bridge.

## Implemented

- Added `RuntimePanelEvidenceBridge` to translate normalized runtime evidence into the mature panel's established report structures.
- Added a framework-neutral `mountRuntimeIntelligencePanel()` that mounts the existing `LdsDebugPanel` for React or any other consumer.
- React owner lifecycle, profiler timing, errors, event timeline/frequency and source attribution now have a direct path into the mature panel.
- The canonical EvidenceStore is exposed to the panel so existing Intelligence/Pinpoint advisor integrations continue to use the shared evidence protocol.
- `lit` is an internal package dependency because the canonical panel is implemented as a LitElement. React consumers do not need to integrate Lit themselves.
- No mature-panel UX was rewritten.

## Evidence semantics

Profiler timings remain framework-reported observations. The bridge does not manufacture update cause or reactive dependency evidence.

## Next

R5.3 activates the framework-independent runtime collectors and bridges their evidence so the mature Network, Vitals, Events, Errors, performance and advisor surfaces become useful in React applications.
