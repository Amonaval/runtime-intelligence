# R5.6 — TrustWeave React Parity Closure

## Outcome

React now consumes the same Runtime Intelligence product rather than a parallel implementation. Practical target: 80–90% of the mature Lit product value, with the remaining gap explicitly tied to framework semantics rather than missing product UI.

## Mature surface parity

| Surface | React status | Notes |
|---|---|---|
| Summary / health / environment | High | Shared browser + mature panel |
| Pinpoint / Fix workflow | High | Shared advisers, errors, network, resource lifetime, tracked-state thrash |
| Intelligence tab / evidence capsule | High | Shared EvidenceGraph, RootCauseGrouper, recorder and presentation |
| Network / Slow API | High | Existing browser collector reused |
| Vitals | High | Existing browser collector reused |
| Console / runtime errors | High | Existing collector + window error/rejection evidence |
| Events | High | UREP timeline/frequency + interactions |
| Perf | High with boundaries | React Profiler timing + source attribution; `withRuntimeIntelligence` makes strategic boundaries cheap |

| Navigation orphan suspicion | High | Shared NavigationBridge; correlation, not proof |
| Network→state | High when state tracked | Shared correlator + `useRuntimeTrackedState` |
| Property watch / reactive dependency cascade | Limited | Lit-native semantics have no honest generic React equivalent without explicit instrumentation |
| Falcor | App-specific | Works only for apps using/integrating Falcor; not a React limitation |

## Final hardening

- Added `profileRoot={false}` so a provider can remain the ownership/runtime root without duplicating nested Profiler timings in Perf.
- Added `withRuntimeIntelligence()` for low-friction strategic component boundaries.
- Shared pipeline now owns/exposes the real UpdateBudgetMonitor used by the mature Intelligence UI.
- Rolling analysis always includes its trigger even after a stronger incident has frozen the recorder.
- Package-surface tests now reflect the intentional packaging boundary: Lit is an internal canonical-panel dependency, React remains optional.
- Added closure regression guards against a second panel and against invented React update/dependency causality.
- Final mission also normalizes formatting/readability of the new shared/React files so the parity work does not leave a compressed-code maintenance burden.

## Honest remaining gap

React does not expose the same native reactive-property dependency semantics as Lit. Runtime Intelligence therefore does not pretend to provide arbitrary property-watch/reactive-cascade causality for uninstrumented hooks. `useRuntimeTrackedState`, `useRuntimeEffect` and `useRuntimeResource` provide explicit stronger evidence where a team wants it, while normal Profiler/browser evidence remains observation/correlation.

## Validation status

Static architecture, source gates and unit/regression tests are included. Real browser dogfood in TrustWeave remains the final product-level checkpoint because this development environment cannot execute the user's local Next.js application.
