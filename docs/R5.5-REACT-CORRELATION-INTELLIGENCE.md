# R5.5 — React Correlation + Intelligence

## Goal

Make React use the same investigation engine as the mature Lit product: evidence graph, root-cause grouping, incident capture, navigation/network correlation, Intelligence tab and evidence capsule.

## Implemented

- Extracted framework-neutral NavigationBridge, NetworkStateCorrelator and developer-intelligence summary into `integration/shared`; Lit paths now re-export them for compatibility.
- Added bounded `RuntimeCorrelationContext` (default 1500 ms) for interaction context only.
- Browser click/change/submit records an interaction ID. Subsequent React update/render observations and network completions inside the bounded window carry that context.
- EvidenceGraph turns shared interaction IDs into `interaction-context` edges marked correlation/temporal-inference. No `causedByEventId` is invented.
- Added shared `RuntimeIntelligencePipeline` using EvidenceGraph, RootCauseGrouper, IncidentFlightRecorder and EvidenceCapsule.
- React runtime starts the shared pipeline and publishes the same `__LDS_INTELLIGENCE__` / `__LDS_INTELLIGENCE_PIPELINE__` contract used by the existing mature Intelligence tab.
- Existing Intelligence-tab presentation is reused through a framework-neutral installer alias.
- Network→state correlation and navigation orphan detection now operate for React via the same shared implementations.
- Explicit resource lifetime violations become UREP lifetime-violation diagnostics as well as mature Pinpoint entries.
- Meaningful shared advisor diagnostics (sequential API, DOM duplication, virtualization, expensive paint, worker opportunity, update budget) can become current Intelligence findings.

## Evidence honesty

Interaction proximity creates correlation context only. Structural owner hierarchy remains structural. Profiler timing remains framework-reported observation. Exact React update cause and reactive dependency causality remain unsupported unless explicit tracked instrumentation supplies stronger evidence.
