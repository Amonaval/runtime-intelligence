# R5.3 — Shared Runtime Surface Parity

## Goal

Make the mature product tabs useful in React by activating existing browser/runtime collectors rather than reimplementing them for React.

## Implemented

- Added `BrowserRuntimeSurface`, shared by architecture rather than tied to Lit semantics.
- React runtime now activates existing Network, Core Web Vitals and console collectors in browser environments.
- Window errors and unhandled promise rejections are normalized into UREP `error` evidence.
- Click/change/submit interactions are recorded as privacy-safe interaction evidence without capturing text or form values.
- Existing network entries are mirrored into UREP so generic advisers and later correlation intelligence can use them.
- Sequential API opportunities are normalized into diagnostics with source attribution when available.
- The mature panel bridge maps slow network observations into the existing Slow API surface while the existing Network/Vitals/Console collectors continue feeding their proven tabs directly.
- Existing DOM duplication, virtualization, paint, worker, idle and update-budget advisers remain shared services.

## Boundaries

This mission does not invent React update cause, hook dependency graphs or component ownership. Those belong to R5.4/R5.5.

## Expected product effect

In a React app the mature panel should now have meaningful data across Summary, Network, Vitals, Console/Errors, Events, Slow API and existing advisor-backed Pinpoint/Intelligence surfaces, in addition to profiler timing from R5.2.
