# R6.1 — Package Contract & Publish Safety

Status: COMPLETE

## Goal

Turn the already-working Git-installed product into a deliberate package contract without prematurely publishing it or splitting it into multiple packages.

## Decisions

1. Keep one package for the R6 baseline: `runtime-intelligence`.
2. Treat these subpaths as the supported public package surfaces:
   - `runtime-intelligence/core`
   - `runtime-intelligence/react`
   - `runtime-intelligence/lit`
   - `runtime-intelligence/panel`
   - `runtime-intelligence/panel/lit`
3. Keep React optional; the canonical panel continues to use Lit internally.
4. Keep the package `private: true` until npm visibility, naming, licensing and IP strategy are explicitly decided.
5. Publish only generic runtime source. `lit/custom` is Syndigo-specific and is intentionally excluded from the root package allowlist.
6. Do not split into `@runtime-intelligence/*` packages yet. A multi-package layout adds release/versioning overhead before it delivers user value.

## Validation contract

Run:

```bash
npm run package:validate
```

The validator checks:

- expected public exports exist;
- export targets exist on disk;
- `lit/src` is present in the package allowlist;
- `lit/custom`, tests, examples and docs do not leak into the packed artifact;
- `npm pack --dry-run --json` contains every exported runtime file;
- accidental npm publication remains blocked by `private: true`.

## Important IP note

Browser-delivered JavaScript cannot be made uncopyable. Minification/obfuscation can only raise copying effort. The repository currently declares MIT licensing; that is intentionally unchanged in this mission. Do not remove the private-package guard or publish publicly until the intended commercial/open-source license is explicitly chosen.

## TrustWeave

No TrustWeave change is required. TrustWeave remains pinned to the validated R5.7.4 SHA while R6 package productization proceeds independently.
