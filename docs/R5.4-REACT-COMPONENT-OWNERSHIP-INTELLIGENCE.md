# R5.4 — React Component & Ownership Intelligence

## Goal

Give React first-class component/effect/resource/state ownership semantics while preserving evidence honesty and reusing the mature Perf, Memory and Pinpoint workflows.

## Implemented

- Added nearest-owner React context beneath every Runtime Intelligence profiler boundary.
- Nested profiler boundaries are linked into an explicit owner hierarchy when both owners are known.
- Added `useRuntimeTrackedState()` to record instrumented update requests and committed state changes without claiming that timing alone proves causality.
- Added `useRuntimeEffect()` for effect lifecycle evidence and error capture.
- Added `useRuntimeResource()` for deterministic resource acquire/release ownership inside an instrumented React boundary.
- Panel compatibility bridge now feeds committed state changes into the mature Perf render-reason drill-down.
- Repeated tracked-state changes are surfaced through the mature property-thrash/Pinpoint path as correlation evidence.
- Resource ownership is tracked per lifecycle generation. Unreleased resources at owner destruction become mature resource-lifetime violations.
- Owner source attribution continues to drive existing file-path navigation.

## Evidence boundaries

These hooks are opt-in instrumentation. Runtime Intelligence does not monkey-patch React hooks or private Fiber internals. Uninstrumented React state/effects therefore remain unsupported rather than guessed.

Profiler duration remains framework-reported observation. `UPDATE_CAUSE` and reactive dependency causality remain unsupported until stronger evidence exists.
