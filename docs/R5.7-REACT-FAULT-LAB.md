# R5.7 — React Fault Lab + Validation Harness

## Goal

Validate React parity without contaminating TrustWeave or weakening evidence honesty.

A random public React sample app is intentionally not the primary harness: its behavior is uncontrolled, its defects are not deterministic, and a missing finding cannot tell us whether the product failed or the sample simply did not exercise the capability.

R5.7 therefore uses two complementary validation layers and a one-pass report workflow.

## R5.7.1 — presentation + export hardening

- React Pinpoint recommendations are framework-aware rather than reusing Lit lifecycle wording.
- Synthetic fallback source paths such as `src/components/div/div.js` are suppressed when there is no real source attribution.
- Worker findings degrade gracefully when no script/function attribution is available.
- Mature panel JSON/HTML buttons export the normalized `runtime-intelligence-report/1` contract.
- The normalized report contains complete UREP evidence, diagnostics, normalized findings, opportunities, Intelligence, evidence capsule and the legacy mature-panel report.

## R5.7.2 — expanded React Fault Lab

### Behavioral faults

The isolated React app now exercises real runtime behavior for:

- slow React render
- rapid tracked-state render storm/update-budget pressure
- bounded effect/state feedback loop
- unhandled Promise rejection
- console warnings + error
- slow fetch
- HTTP 503 fetch
- sequential fetch calls
- large response + CPU/long-task work
- XHR 503 failure
- duplicate singleton/dialog DOM
- large unvirtualized list
- oversized DOM
- expensive CSS/paint pattern
- tracked resource lifetime violation
- retained same-name component-owner/mount spike

### Deterministic rare-signal injection

`injected-scenarios.js` remains explicitly labeled `fault-lab-injected` and covers:

- interaction/update correlation
- slow render
- state thrash
- slow + failed network evidence
- DOM duplication
- virtualization
- expensive paint
- worker opportunity
- sequential API opportunity
- update-budget violation
- idle scheduling opportunity
- paint timing
- network correlation / orphan-suspect diagnostics
- runtime error
- resource lifetime violation
- retained-owner/mount spike

Synthetic evidence is for product validation only and must never be interpreted as an observed defect in a consumer application.

## One-pass workflow

Run:

```bash
npm run lab:react:install
npm run lab:react
```

Open `http://127.0.0.1:4178` and click **Run all + export JSON + HTML**.

The runner triggers behavioral faults, waits for asynchronous evidence, injects rare deterministic scenarios, refreshes the mature panel and requests both normalized reports. If the browser blocks multiple automatic downloads, use the adjacent explicit JSON and HTML export buttons after the run.

## Framework adoption principle

The Fault Lab pattern is reusable for future adapters. Vue, Angular and other framework labs should implement the same normalized scenario contract and export the same report schema while using framework-specific adapters underneath.

See `docs/FRAMEWORK-ADOPTION-LADDER.md` for the required vs optional instrumentation levels.
